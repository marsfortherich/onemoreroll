# One More Roll

**A push-your-luck dice roguelite.** Reforge the faces of your dice, stack charms that
multiply each other, and decide — every single turn — whether to bank what you have or
take one more roll.

Vanilla HTML/CSS/JS. No build step, no dependencies, no network calls, no image files,
no audio files. Open `index.html` and play.

> **[▶ Play it](https://onemoreroll.marsindustries.dev/)** — live once Pages
> finishes its first deploy (see [Deploying](#deploying)).

```bash
start index.html                 # or: python tools/serve.py  →  http://localhost:8123
```

**Content:** 91 charms · 12 decks · 8 perils · 19 boss blinds · 20 omens · 14 runes ·
20 relics · 21 boons · 7 booster packs.

See [ROADMAP.md](ROADMAP.md) for what is built, what isn't, and what is worth doing next.

## The loop

Beat **8 Antes**. Each Ante has a **Small Blind**, a **Big Blind** and a **Boss Blind**,
each with a score target you must reach before running out of turns.

A **turn** is one round of dice:

1. Your dice are rolled automatically.
2. Click dice to **hold** them, then **Reroll** the rest (2 rerolls by default).
3. Commit the dice to a **category** on the scorecard.

Each of the 13 categories can be used **once per blind**. You get 5 turns, so you pick
your five best. Scoring a category your dice do not satisfy *scratches* it for 0.

Between blinds you visit the **shop**.

## Scoring

```
score = (category base Pips + dice pips + bonuses)  ×  (category base Fortune + bonuses)
```

Every category has a **level**. Levelling it raises both its base Pips and its base
Fortune permanently, for the rest of the run — this is the main way scores keep pace
with the ante curve.

Only *scoring* dice add their pips: for **Sixes** that is the dice showing 6, for
**Small Straight** the four dice in the run, for **Chance** all of them. Dice that do
not score are "held" and can still matter (Steel dice, Steel Nerves).

**Charms fire left to right and order matters** — drag them to rearrange. Putting
`+Fortune` before `XFortune` is worth a lot more than the reverse.

## What you collect

| Thing | What it does |
|---|---|
| **Charms** | 91 of them across four rarities: flat Fortune, XFortune, retriggers, economy, scaling engines. Right-click to sell, drag to reorder. |
| **Runes** | Consumable. Permanently level up one category. |
| **Omens** | Consumable. Modify a single die — enhancements, editions, seals, face values, duplication, destruction. |
| **Relics** | Permanent run upgrades, in two tiers — a tier-2 relic only appears once you own its tier-1. |
| **Booster packs** | Pick 1–2 of several Charms / Runes / Omens / die stamps. |
| **Boons** | 21 of them, gained by skipping a Small or Big Blind. |

### Die upgrades

- **Enhancements** — Bonus (+30 Pips), Fortune (+4 Fortune), Glass (X2 Fortune, may
  shatter), Gold ($3), Steel (X1.5 Fortune while *unscored*), Lucky (1-in-5 for +20
  Fortune), Stone (+50 Pips and always scores, whatever the category).
- **Editions** — Foil (+50 Pips), Holographic (+10 Fortune), Polychrome (X1.5 Fortune).
- **Seals** — Red (retrigger), Gold ($3), Blue (creates a Rune).
- **Faces** — The Chisel raises a die's lowest face; The Lathe makes every face the same
  value. A die is just a list of six faces, so it can be reshaped. This is the design
  space the game is really built around.

If your pool grows past five dice, the game automatically scores the best five-die
subset for whichever category you choose; the leftovers count as held.

## Decks and perils

**12 decks** change how a run opens — Loaded (no ones on any die), Quarry (two Stone
dice), Scholar (every category starts at level 3, one fewer Charm slot), Wide (seven
dice but 20% higher targets), Glass, Gambler, Miser, Plated, Abacus, Magpie, Anarchy.
All but Standard are unlocked by concrete achievements.

**8 perils** stack cumulatively: no Small Blind reward, +10% targets, +25% prices, −1
turn, +15% more targets, halved interest and $0 start, −1 reroll. Winning at one peril
unlocks the next.

## Boss blinds

19 of them, each a different constraint: fewer rerolls or turns, disabled categories, a
nullified section, hidden dice, halved base values, no money, a die confiscated for the
blind, levels drained as you score. Ante 8 always ends on **The Grand**.

## Art

There is not a single image file in the repo. Everything is drawn at runtime:

- **Icons** — 104 hand-authored SVG icons (`js/icons.js`) on a 24×24 grid, stroke-first
  and monochrome via `currentColor`, so CSS tints them per rarity. They are grouped into
  families on purpose: Fortune charms share the flame family, economy charms share the
  coin family, and each scoring category has its own mark that its Rune reuses.
- **Texture** — felt weave, paper fibre and film grain are generated by SVG
  `feTurbulence` filters embedded as data URIs.
- **Materials** — a Gold die is a metallic gradient with a specular band, Glass is
  translucent with a highlight streak, Steel is brushed, Stone is noisy rock, and
  Polychrome animates a real hue shift.
- **Asymmetry** — cards and dice rest at small fixed rotations so the table looks dealt
  rather than laid out. Disabled under reduced motion.

`css/style.css` owns layout and component structure; `css/art.css` owns the look.
Open `tools/icons.html` to browse the whole icon sheet.

## Audio

Every sound is **synthesised at runtime** from oscillators and filtered noise. The music
is a live four-mode sequencer (menu, play, shop, boss) built from a pad, a bass and a hat
over a chord progression. Browsers require a gesture before audio starts, so it comes in
on your first click.

## Settings

Master / SFX / music volume, animation speed (Normal / Fast / Instant), screen shake,
particles, reduced motion, high contrast, and scoring-dice highlighting. Reduced motion
defaults to your OS `prefers-reduced-motion` setting.

## Keys

`1`–`8` hold a die · `R` / `Space` reroll · `Enter` score the selected category ·
`S` sort dice · `Esc` close an overlay

## Saving

The run auto-saves to `localStorage` after every action, and the title screen offers
**Continue Run**. Saves are versioned and migrated; a corrupted save is discarded rather
than bricking the title screen. Runs are seeded — same seed, same run.

## Deploying

The repo is a static site with relative paths, so GitHub Pages serves it as-is.

1. Create a repo named **`onemoreroll`** and push this folder to `main`.
2. **Settings → Pages → Source: GitHub Actions.** This step is manual and unavoidable:
   the workflow's default `GITHUB_TOKEN` cannot switch Pages on for a repo (that needs
   admin scope), so the first deploy fails with *"Resource not accessible by
   integration"* until the toggle is flipped by hand. Re-run the workflow afterwards.
3. The included workflow (`.github/workflows/pages.yml`) runs the test suite and a
   balance smoke run, then deploys. **A failing test blocks the deploy.**
4. The `CNAME` file binds the site to <https://onemoreroll.marsindustries.dev/>;
   without it Pages would serve at `marsfortherich.github.io/onemoreroll/` instead.

```bash
git remote add origin https://github.com/marsfortherich/onemoreroll.git
git push -u origin main
```

### Shipping an update

GitHub Pages sets caching headers on `js/` and `css/`, so a returning player can keep
running the old build indefinitely. Every asset URL in `index.html` carries a `?v=`
token — bump it before you push:

```bash
node tools/bump.js          # 1.0.0 -> 1.0.1
node tools/bump.js 1.1.0    # or set it explicitly
```

The version is shown on the title screen, which makes bug reports much easier to place.

### Deliberately not included

- **No service worker.** Offline play would be nice, but a stale-cache bug on a site
  with no backend leaves players stuck on a broken build with no recourse. The `?v=`
  scheme solves the real problem without that risk.
- **No `LICENSE` file.** A public repo with no licence is "all rights reserved", which is
  a valid default — but if you want others to fork or contribute, add one.
- **No `og:image`.** Link previews show text only until a real share image exists.
- **Not yet mobile-ready.** The layout reflows down to phone width, but the game still
  leans on hover for tooltips and right-click to sell. Phase 5 in the roadmap.

### Code terms vs player terms

Some internal identifiers still use the names the code was written with. They are stable
on purpose — renaming them would churn the save format and the test suite for no player
benefit. The mapping:

| In code | On screen |
|---|---|
| `chips` | Pips |
| `mult` | Fortune |
| `voucher` | Relic |
| `tag` | Boon |
| `stake` | Peril |

The one exception is the `fiveKind` category, which *was* renamed in code — its old
identifier was a registered trademark. Existing saves are migrated automatically.

### Tooling

The logic layer has no DOM dependencies, so it loads into Node with stubbed
`UI`/`localStorage`/`Sfx` and runs headlessly.

```bash
node tools/test.js                              # 72 tests
node tools/sim.js --runs 300                    # balance batch
node tools/sim.js --runs 200 --stakes 1,3,5,8   # difficulty ladder
node tools/sim.js --runs 120 --all-decks        # per-deck difficulty
node tools/tune.js 300                          # compare ante curves
node tools/bump.js                              # bump the asset version
python tools/serve.py 8123                      # no-cache dev server
```

| File | Role |
|---|---|
| `tools/harness.js` | Loads the logic layer into a Node `vm` context with stubs |
| `tools/policies.js` | Bot policies: `random`, `greedy`, `competent` |
| `tools/test.js` | Scoring, determinism, persistence, migration, content integrity |
| `tools/sim.js` | Batch simulation and reporting |
| `tools/tune.js` | A/B a balance parameter across several values |
| `tools/bump.js` | Bump the cache-busting asset version |
| `tools/icons.html` | Icon sheet — browse every icon at size |
| `tools/serve.py` | No-cache dev server (browsers cache `js/` hard during a visual pass) |

The test suite exercises **every** charm, boon, relic, boss, omen, rune, deck and peril,
so adding content that throws will fail the build — and therefore block the deploy.

### Adding a charm

Append one entry to `MORE_CHARMS` in `js/content-extra.js`; it is automatically added to
the shop pool, weighted by rarity, and picked up by the tests. Give it an icon in
`CHARM_ICONS` in `js/icons.js`.

```js
{
  id: 'my_charm', name: 'My Charm', rarity: 'uncommon',
  desc: function (charm, run) { return '<span class="m">+10 Fortune</span>'; },
  onScore: function (ctx, c) { ctx.addMult(10, c); }
}
```

Available hooks: `onDieScored`, `onDieHeld`, `onScore`, `retrigger`, `onTurnEnd`,
`onBlindStart`, `onBlindEnd`, `onReroll`, `onBuy`, `onSell`, plus `init` for scaling
state and `passive` for engine-level flags. Effects go through `ctx.addChips`,
`ctx.addMult`, `ctx.xmult` and `ctx.earn` so they appear in the scoring animation and
play the right sound.

Scoring runs twice: once as a **preview** (`commit: false` — no RNG, no money, no
mutation) to fill the scorecard, and once for real. Guard anything random or permanent
behind `ctx.commit`.

## Credits

A browser roguelite experiment. The run structure — escalating blinds, a shop between
them, and a build assembled from stacking modifiers — owes an obvious debt to
**Balatro**. The dice, the scorecard-as-a-resource, and the editable die faces are this
game's own.

## Part of the Roguelike Arcade

One More Roll shares a design system, a sign-in and a leaderboard with the other games
in the arcade. That layer lives in `shared/` and is a synced copy — edit the
canonical one at the arcade root and run `python tools/sync-shared.py`. See
`ARCADE.md` at the arcade root for the full picture, including Firebase setup.

Without a Firebase config the arcade reports "Offline" and the game plays exactly
as it always has, entirely from `localStorage`.
